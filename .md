# Brivane Labs: Pacotes dos Apps de Workspace

## Identificador base

```
com.brivanelabs.<nomedoapp>
    ```
    
    Vale para Android (`applicationId`) e iOS (Bundle ID).
    
    ## Regras do identificador
    
    - Tudo em minúsculas, sem espaços, acentos ou hífens
    - Só letras, números e pontos
    - Cada parte deve começar com letra
    - Depois de publicado, não pode ser alterado
    - Deve bater com um domínio que você controle (`brivanelabs.com`)

    ## Configuração no Android (`build.gradle`)
    
    ```gradle
    android {
    defaultConfig {
    applicationId "com.brivanelabs.notes"
    }
    buildTypes {
    debug {
    applicationIdSuffix ".dev"
    }
    }
    }
    ```
    
    ## Um app ou vários?
    
    | Abordagem | Vantagem | Desvantagem |
    |---|---|---|
    | Vários apps (docs, sheets, tasks...) | Cada um leve e focado, melhor nas buscas das lojas | Mais publicações e manutenção |
    | Um app só (`workspace`) | Um cadastro nas lojas, experiência unificada | App pesado, difícil de atualizar por partes |
    
    ## Aviso sobre nomes
    
    Termos como `docs`, `sheets`, `slides`, `drive`, `meet` e `keep` são nomes de produtos do Google Workspace. No identificador do pacote isso não é problema, mas o nome exibido do app na loja pode gerar conflito de marca ou ser recusado. Use nomes próprios, como "Brivane Notes" ou "Brivane Tasks".
    
    ## Checklist antes de publicar
    
    - [ ] Registrar `brivanelabs.com` e `brivanelabs.com.br`
    - [ ] Consultar o INPI (classes 9, 35 e 42)
    - [ ] Se for atuar fora, consultar USPTO e EUIPO
    - [ ] Definir se serão vários apps ou um app único
    - [ ] Escolher os 1 a 2 apps que serão lançados primeiro
    - [ ] Confirmar o ID final antes de publicar (não pode mudar depois)
